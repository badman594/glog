# glog — fast log counting in the Goose language

`glog` is a tiny command-line tool for counting and grouping
[Common Log Format](https://en.wikipedia.org/wiki/Common_Log_Format)
web server logs. It is written in [Goose](https://github.com/aardappel/goose),
an experimental memory-safe systems language with no heap allocator
and no garbage collector.

Despite the language being weeks old, `glog` is not a toy:
on a real log file it outruns both the tools people actually use
and low-level native utilities.

## What it does

| Command | Result |
|---|---|
| `goose glog.goose -- count access.log` | total number of log lines |
| `goose glog.goose -- count_by path access.log` | line count per URL path |
| `goose glog.goose -- where_ge 500 access.log` | lines with HTTP status >= 500 |

Malformed lines are never fatal — they are counted and reported:

```
total lines: 818730
skipped bad lines: 54582
```

## Requirements

The [Goose compiler](https://github.com/aardappel/goose) v2026.3 or later
(prebuilt binaries for Windows / macOS / Linux on the releases page).
In-process runs need nothing else.

## Benchmarks

Test machine: an ordinary home desktop, Windows 10.
`glog` is run via `goose glog.goose ...`, so **every glog time below
includes compiler startup** (parsing + typechecking + JIT).

Input file: `big.log`, 873,312 log lines (~61 MB), generated by repeating
the included `small.log` sample.

| Task | Tool | Time |
|---|---|---|
| Group lines by URL path | **glog** | **0.64 s** (median of 10 runs) |
| same task | PowerShell pipeline (`Get-Content \| ForEach-Object \| Group-Object`) | 91.5 s — **143x slower** |
| Count 5xx responses (163,746 matches) | **glog** | **0.57 s** |
| same task | `Select-String` | 1.49 s — 2.6x slower |
| same task | `findstr` (native C tool, raw byte search, **no parsing**) | 0.76 s — **1.3x slower** |
| Group by path on a 9x larger file (7,859,808 lines, ~552 MB) | **glog** | **5.16 s** (~1.5 M lines/s) |

Notes for the sceptical:

- The `findstr` comparison is favourable to `findstr` in terms of work
  (it does not parse the line), yet `glog` is still faster while fully
  parsing every line.
- Throughput scales linearly with input size (0.64 s -> 5.16 s for 9x data).
- The two non-glog tools produced identical counts to `glog` on every run,
  so the comparison is about speed, not semantics.
- All commands used for the measurements are shown above; reproduce and
  contradict them, that is what benchmarks are for.

## How it works (why it is fast)

- The file is read once into a single buffer; every parsed field is a
  *slice* into that buffer. Zero per-line string allocations.
- `count_by` keys are slices into the file buffer stored directly in a
  hash table — strings are never copied.
- Parsing is a hand-written single pass over bytes: no regular expressions.
- The whole program is ~100 lines, no dependencies, no build step.

## Status

Early. The language it is written in is itself a month old. API and
syntax may change. Treat this as a demonstration that Goose's memory
model (inline data, no heap, no GC) translates into real, measurable
speed on allocation-heavy text workloads.
